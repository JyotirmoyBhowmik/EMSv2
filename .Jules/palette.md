## 2026-06-02 - Accessible Custom Inputs and Auth Providers
**Learning:** Custom interactive elements (like auth provider cards) in the WebUI are frequently built using non-semantic `<div>` tags which inherently lack keyboard focus and semantic meaning. Similarly, form `<label>` and `<input>` elements frequently miss proper associations (`htmlFor` and `id`). This creates major accessibility hurdles for keyboard and screen reader users navigating forms and selections.
**Action:** Always convert generic non-semantic `<div>` elements behaving as buttons into native `<button>` elements (e.g. `type="button"`, and include ARIA properties like `aria-pressed` for selection states). Also, systematically link forms `<label>` elements to their related `<input>` fields using unique `id` and matching `htmlFor` attributes across the WebUI components.
